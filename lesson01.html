🍱 두근두근 급식실 ← 목차 학생용
공통 대시보드 · 1차시

우리 학교 급식으로 어떤 앱을 만들 수 있을까?

지난달에 배추김치가 며칠 나왔는지 궁금한 학생도 있고, 오늘 처음 급식실에 와서 식판을 어디에 놓아야 할지 모르는 학생도 있습니다. 첫 번째 학생에게는 날짜별 식단을 살펴볼 수 있는 화면이, 두 번째 학생에게는 우리 학교의 식판 반납 순서를 알려 주는 화면이 필요합니다. 오늘은 앱의 첫 화면을 만들고, 짝이 자기 휴대폰으로 그 화면을 열어 볼 수 있게 합니다.

🎯 오늘 하는 것
  • 8차시 동안 만들 공통 대시보드와 팀 앱을 살펴봅니다.
  • ‘급식실 열기’ 버튼을 누르면 인사말이 나오는 앱을 만들고, 인사말을 우리 반 문장으로 바꿉니다.
  • 두 파일을 배포한 뒤, 짝의 휴대폰에서 바뀐 인사말을 확인합니다.

0. 오늘의 목표

  • 공통 대시보드와 팀 앱에서 누가 어떤 일을 할 수 있는지 예를 들어 설명할 수 있습니다.
  • 원하는 동작을 AI에 요청하고, 버튼을 누르기 전과 누른 뒤의 화면을 비교해 요청대로 작동하는지 확인할 수 있습니다.
  • 앱을 배포하고, 다른 사람이 앱 주소를 열어 내가 고친 문구를 읽을 수 있는지 확인할 수 있습니다.

1. 8차시 동안 만들 것

1~4차시에는 같은 앱을 이어서 고칩니다

공통 대시보드에서 답할 질문은 “지난달 우리 학교 급식에 가장 자주 나온 반찬은 무엇일까?”입니다. 10월 1일 식단에 배추김치가 있고 10월 2일 식단에도 배추김치가 있다면, 이틀 동안 배추김치가 나온 날은 2일입니다. 한 달치 식단을 모으면 반찬마다 제공한 날을 세어 비교할 수 있습니다. 대시보드에는 그 결과를 보여 주는 그래프와 날짜를 확인할 수 있는 식단 표를 함께 둡니다.

차시만드는 사람의 일앱을 여는 사람이 할 수 있는 일
1차시 · 공통제목과 버튼이 있는 첫 화면을 만들어 배포합니다.휴대폰에서 주소를 열고 버튼을 눌러 인사말을 읽습니다.
2차시 · 공통같은 앱에 학교 검색과 지난달 중식 조회를 추가합니다.학교와 지역을 확인하고, 원하는 날짜의 점심 메뉴를 찾습니다.
3차시 · 공통반찬별 제공 일수를 세어 그래프로 나타냅니다.1위 반찬을 찾고, 식단 표에서 실제로 나온 날짜를 확인합니다.
4차시 · 공통친구가 설명 없이 1위 반찬을 찾는 모습을 보고 화면 한 곳을 고칩니다.어느 달의 결과인지 확인하고 그달에 가장 자주 나온 반찬을 말합니다.
5~6차시 · 팀급식실에서 도울 사람과 상황을 정하고, 그 사람에게 필요한 기능 하나를 만듭니다.팀이 정한 일을 해 봅니다. 예를 들어 처음 가는 반납대에서 식판을 놓을 순서를 찾습니다.
7~8차시 · 팀친구가 사용하다 멈춘 곳을 고치고, 다른 친구에게 같은 일을 부탁해 결과를 확인합니다.완성한 앱에서 핵심 기능을 직접 사용하고 결과를 보여 줍니다.

5~8차시에는 팀마다 도울 사람을 정합니다

배식 순서를 안내하는 선생님은 어느 학년이 다음 차례인지 확인해야 합니다. 급식 도우미는 처음 맡은 날에 무엇부터 준비해야 할지 궁금할 수 있습니다. 같은 급식실에서도 누구의 어떤 일을 도울지에 따라 첫 화면에 쓸 말과 버튼이 달라집니다. 팀이 반납 순서나 준비 절차를 안내하기로 했다면, 학교에서 확인한 절차만으로도 앱을 만들 수 있습니다.

“식판을 처음 반납하는 친구가 휴대폰을 열었습니다. 첫 화면에서 무엇을 볼 수 있으면 좋겠습니까?”
두근의 질문 우리 학교 반납대를 떠올려 보세요. 짝과 버튼 이름을 하나씩 제안하고, 그 버튼을 누르면 어떤 안내가 나와야 하는지 말해 보세요.

2. 바이브코딩 ①②③

오늘 연습할 순서는 원하는 동작을 요청하기, 실행한 화면 확인하기, 한 가지를 고쳐 다시 확인하기입니다. 학교에서 사용하는 AI 도구에 새 대화를 여세요. 4차시까지 이 대화에서 같은 앱을 이어서 고칩니다.

  1. ① 첫 화면을 요청합니다

    앱을 처음 연 사람에게 무엇이 보이고, 그 사람이 버튼을 누르면 무엇이 더 보일지 생각해 보세요. 아래 요청에는 화면에 쓸 문장과 그 문장을 보여 줄 때가 정해져 있습니다.

    ① 첫 화면 프롬프트
    스트림릿으로 급식실 앱을 만들어 줘. 제목은 ‘두근두근 급식실’, 버튼 이름은 ‘급식실 열기’로 해 줘.
버튼을 누르면 ‘우리 학교 급식실에 오신 걸 환영합니다!’라는 문장이 나오게 해 줘.
앱을 준비하는 첫 줄 다음에는 이 동작을 세 줄 정도로 작성해 줘.
실행할 파일 main.py와 설치 목록 requirements.txt의 내용을 나누어 보여 줘.

    응답에서 파일 이름을 먼저 찾으세요. main.py에는 화면을 만드는 내용이, requirements.txt에는 배포할 컴퓨터에 설치할 프로그램의 이름이 들어갑니다. 각 파일의 내용만 일반 텍스트로 저장하세요. AI의 설명이나 코드 앞뒤의 역따옴표가 파일에 들어가면 실행할 때 오류가 날 수 있습니다.

  2. ② 화면에서 확인할 것

    두 파일을 처음 실행하는 방법은 3. 첫 배포에 있습니다. 그 절을 따라 앱을 연 뒤, 환영 문구를 고치기 전에 아래 세 가지를 차례로 확인하세요.

    • 앱을 처음 열었을 때 제목이 두근두근 급식실이고, 제목 아래에 급식실 열기 버튼이 하나 보입니까?
    • 버튼을 누르기 전에는 환영 문구가 보이지 않습니까?
    • 버튼을 한 번 누르면 우리 학교 급식실에 오신 걸 환영합니다!가 버튼 아래에 표시됩니까?

    환영 문구가 처음부터 보였다면 버튼을 누르기 전과 누른 뒤의 화면이 같습니다. 이때 확인할 부분은 문장의 철자보다 언제 표시되는가입니다. 아래 기준 코드에서 버튼을 확인하는 줄과 문장을 표시하는 줄을 찾아보세요.

    기준 코드 펼치기 · main.py와 requirements.txt

    첫 화면을 확인할 때 사용하는 두 파일입니다. 파일마다 따로 복사하세요.

    import streamlit as st
st.title("두근두근 급식실")
if st.button("급식실 열기"):
    st.write("우리 학교 급식실에 오신 걸 환영합니다!")
    streamlit

    main.py의 첫 줄은 스트림릿을 불러옵니다. 그 아래 세 줄이 제목을 표시하고, 버튼을 눌렀는지 확인하고, 눌렀을 때 인사말을 표시합니다. 마지막 줄 앞의 빈칸은 그 줄을 버튼을 눌렀을 때만 실행한다는 뜻입니다. 복사할 때 이 빈칸도 함께 옮기세요.

  3. ③ 환영 문구를 우리 반 말로 바꿉니다

    짝과 인사말을 하나 정하세요. 예를 들어 “우리 반 여러분, 맛있게 드세요!”라고 쓸 수 있습니다. 아래 대괄호를 지우고 그 안에 정한 문장을 넣어 같은 대화에 요청하세요.

    ③ 개선 프롬프트
    버튼을 누른 뒤에 보이는 환영 문구를 ‘[우리 반이 정한 인사말]’로 바꿔 줘.
제목과 버튼 이름은 지금과 같게 해 줘. 고친 main.py 전체를 보여 줘.

    새 파일에서 제목, 버튼 이름, 인사말을 차례로 읽으세요. 첫 두 항목은 처음 화면과 같고 인사말만 바뀌었습니까? 이제 배포에 쓴 저장소에서 main.py를 고쳐 저장하고, 같은 앱 주소에서 결과를 확인합니다.

3. 첫 배포

배포하면 짝이 자기 휴대폰에 프로그램을 설치하지 않고도 주소를 열어 앱을 쓸 수 있습니다. GitHub에는 앱을 만드는 파일을 올립니다. Streamlit Community Cloud는 그 파일을 읽어 실행하고 앱 주소를 제공합니다. 계정 가입이나 두 서비스 연결을 마치지 못했다면 먼저 시작 전 준비를 따라 하세요.

  1. GitHub에 새 저장소를 만듭니다

    GitHub의 새 저장소 만들기를 여세요. 소유자에 수업용 공개 별명이 표시되는지 확인하세요. 저장소 이름은 lunch-app처럼 앱을 설명하는 말로 정하고 Public을 선택한 뒤 Create repository를 누르세요. 저장소 이름과 계정 이름은 주소에도 표시됩니다.

  2. 두 파일을 올립니다

    빈 저장소의 uploading an existing file을 누르세요. 이미 파일 목록이 있다면 Add file에서 Upload files를 고르세요. ①에서 받은 main.py와 requirements.txt를 올립니다. 폴더 안에 넣지 말고 저장소를 열었을 때 두 파일이 바로 보이게 하세요.

    공개하기 전 두 파일의 내용에 이름, 학번, 인증키가 없는지 읽어 보세요. 변경 설명에는 ‘첫 화면 추가’라고 적고 Commit changes를 누르세요. 이렇게 변경한 내용을 기록하는 일을 커밋이라고 합니다. 파일 목록에서 main.py.txt처럼 확장자가 한 번 더 붙지 않았는지 확인하세요.

  3. Streamlit Community Cloud에서 앱을 실행합니다

    share.streamlit.io에 연결한 GitHub 계정으로 로그인하세요. New app을 누르세요. 화면에 Create app이 보이면 그 버튼을 누르고 GitHub 저장소에서 배포하는 항목을 고르세요.

    배포 화면의 항목선택하거나 입력할 값
    Repository · 저장소내 공개 별명 아래에 방금 만든 저장소를 고릅니다.
    Branch · 브랜치GitHub 파일 목록 위에 표시된 브랜치 이름을 고릅니다. 보통 main입니다.
    Main file path · 실행 파일 경로저장소 첫 화면에 올린 main.py를 입력합니다.

    Deploy를 누른 뒤 앱 제목과 버튼이 보일 때까지 기다리세요. 앱을 열어 ②의 세 항목을 확인한 다음 ③의 개선 프롬프트로 우리 반 인사말을 받으세요.

  4. 인사말을 바꾸고 짝의 휴대폰에서 같은 주소를 엽니다

    GitHub에서 main.py를 열고 연필 모양의 편집 버튼을 누르세요. 내용을 ③에서 받은 파일 전체로 바꾼 뒤, 변경 설명을 ‘환영 문구 수정’으로 적어 배포에 연결한 브랜치에 커밋하세요. 기존 앱에 변경 내용이 반영되면 앱을 새로 열고 버튼을 눌러 보세요.

    4절의 공개 전 점검을 마친 뒤, 앱을 열어 둔 탭의 주소가 .streamlit.app으로 끝나는지 확인해 짝에게 보내세요. 짝에게 “버튼을 눌러 나온 인사말을 읽어 주세요”라고 부탁하세요. 우리 반이 정한 문장이 들리면 다른 기기에도 수정 내용이 반영된 것입니다.

4. 공개 전 점검

파일을 올리기 전에는 내 컴퓨터에서, 링크를 보내기 전에는 저장소와 실행 화면에서 확인하세요. 버튼을 누른 뒤에만 보이는 내용까지 살펴봅니다.

  • 저장소를 엽니다. 주소와 저장소 설명을 읽고 두 파일을 각각 열어 봅니다. 파일 내용과 커밋 설명에 학생 이름, 학번, 인증키가 없는지 확인합니다. 오늘 앱에는 인증키가 필요하지 않습니다.
  • 앱을 새로 엽니다. 제목과 버튼을 읽고 버튼을 한 번 누릅니다. 화면 어디에도 이름이나 학번을 요구하는 입력란이 없고, 인사말에도 개인을 알아볼 정보나 인증키가 없는지 확인합니다.
  • 확인한 주소를 짝에게 보냅니다. 짝의 휴대폰에서 버튼을 누르고 바뀐 인사말을 읽습니다. 둘이 읽은 문장이 같으면 앱 주소를 다음 시간에 찾을 수 있도록 수업용 북마크에 저장합니다.

공개 저장소에 실제 인증키를 올린 사실을 발견하면 링크 공유를 멈추고 선생님께 알리세요. 파일을 수정해도 이전 커밋에 키가 남을 수 있으므로 해당 키를 폐기하고 새로 발급받아야 합니다.

막힐 때 펼쳐 보세요

배포에 실패했습니다

배포 설정에 쓴 브랜치와 실제로 파일을 올린 브랜치가 같은지 확인하세요. GitHub에서 두 파일이 보이는데 실행 파일을 찾지 못한다면 Main file path와 실제 파일 이름을 한 글자씩 비교하세요. Main.py와 main.py는 서로 다른 이름입니다.

실행 파일을 찾은 뒤에도 실패하면 Manage app에서 실행 기록을 여세요. 마지막 오류 줄에서 파일 이름과 줄 번호를 찾습니다. AI에 물을 때에는 계정 정보나 인증키가 보이지 않는 오류 문장만 사용하세요.

배포 오류를 확인하는 프롬프트
첫 급식 앱을 배포하는 중에 ‘[오류 문장]’이라는 안내가 나왔어. 이 문장을 보고 내가 먼저 확인할 파일이나 설정 하나와 확인 방법을 알려 줘.
실행 기록에 ModuleNotFoundError가 표시됩니다

앱에서 사용하려는 프로그램을 실행 환경에서 찾지 못했다는 뜻입니다. 오류 줄 끝에 적힌 이름을 읽으세요. GitHub에서 requirements.txt를 열어 이름을 정확히 붙였는지, main.py와 같은 폴더에 있는지 확인하세요.

기준 코드의 설치 목록에는 소문자로 streamlit 한 줄만 들어갑니다. AI가 급식 조회나 그래프까지 추가했다면 먼저 ②의 기준 코드와 비교해 오늘 필요한 제목, 버튼, 인사말만 남기세요. 두 파일을 고쳐 커밋한 뒤 같은 앱을 다시 여세요.

짝의 휴대폰에서 링크가 열리지 않습니다

짝의 휴대폰 주소창을 함께 보세요. github.com은 파일을 보는 곳이고 share.streamlit.io는 앱을 관리하는 곳입니다. 내 컴퓨터에서 급식실 버튼이 보이는 앱을 열어 그 탭의 .streamlit.app 주소를 다시 보내세요.

주소가 맞는데 짝에게 로그인 화면이 나오면 앱의 공유 설정에서 링크를 받은 사람이 볼 수 있는지 확인하세요. 앱이 대기 상태라는 안내가 나오면 화면의 실행 버튼을 누르고 기다리세요. 같은 주소가 학교망에서 열리지 않으면 주소와 화면에 나온 안내를 선생님께 보여 드리세요.

AI 딴소리 멈추기 한 줄

첫 화면을 요청했는데 식단 검색이나 회원 가입까지 추가했다면, 같은 대화에 다음 한 줄을 보내세요.

요청 범위 다시 알려 주기
이번에는 제목, ‘급식실 열기’ 버튼, 버튼을 눌렀을 때 나오는 인사말만 남겨서 main.py와 requirements.txt를 다시 보여 줘.

오늘 정리

오늘 만든 첫 화면은 4차시까지 이어서 쓸 공통 대시보드의 첫 부분입니다. 5차시부터는 팀마다 도울 사람을 정하고, 그 사람이 급식실에서 할 일 하나를 골라 새 앱을 만듭니다.

오늘의 결과는 짝이 읽은 문장으로 확인할 수 있습니다. 짝이 처음 인사말을 읽었다면 주소는 열렸지만 수정 내용은 아직 확인하지 못한 것입니다. GitHub에서 마지막으로 저장한 인사말을 확인하고, 짝의 휴대폰에서 같은 주소를 새로 연 뒤 버튼을 다시 눌러 보세요.

확인 문제

문제 1 5~8차시에 만들 팀 앱의 예로 수업 목적에 가장 잘 맞는 것을 고르세요.
두 번째 예에는 도울 사람과 그 사람이 할 일이 모두 정해져 있습니다. 처음 온 학생에게 앱을 건네고 실제로 반납 순서를 찾는지 확인할 수 있습니다.
문제 2 앱을 열자마자 제목, 버튼, 환영 문구가 모두 보입니다. ②에서 확인할 내용으로 알맞은 것을 고르세요.
요청에는 환영 문구를 보여 줄 조건이 있습니다. 앱을 처음 열었을 때는 제목과 버튼이 보이고, 버튼을 눌렀을 때 인사말이 추가되어야 합니다.
문제 3 짝이 받은 주소를 열었더니 main.py와 requirements.txt의 파일 목록이 보입니다. 어느 주소를 다시 보내고, 짝에게 무엇을 부탁하겠습니까?
짝에게 설명한 뒤 예시 답 펼쳐 보기

파일 목록은 GitHub 저장소 화면입니다. ‘급식실 열기’ 버튼이 보이는 앱을 열고 그 탭의 .streamlit.app 주소를 보냅니다. 짝에게 휴대폰에서 버튼을 누른 뒤 우리 반이 정한 인사말을 읽어 달라고 부탁합니다.
