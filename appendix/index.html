파일 목록이 보이면 GitHub 저장소의 주소를 보낸 것입니다. 실행 중인 앱 탭에서 .streamlit.app 주소를 복사하세요. 앱은 열리는데 예전 문구가 보이면 배포에 연결한 브랜치에서 7차시에 고친 파일을 확인하세요. 수정 내용이 반영된 뒤 짝 팀의 기기에서 주소를 다시 열고 과제를 한 번 수행하세요.

시연할 화면이 열리지 않을 때
짝 팀이 링크를 열었더니 [실제로 본 화면]이 나와. 7차시에 고친 앱으로 시연하려면 어떤 주소나 배포 설정을 먼저 확인할지 알려 줘.

8차시 제출 카드에 짝 팀이 열어 본 주소 적기

③ 공개 전 점검표

GitHub에 파일을 올리기 전에 한 번, 배포한 앱 주소를 보내기 전에 한 번 확인하세요. 팀원 한 명은 파일을 열고 다른 한 명은 첫 화면부터 결과 화면까지 살펴보세요. 브라우저에서 인쇄하면 첫 장에 점검표가, 다음 장에 선택 활동 보고서가 나옵니다. 점검표만 필요하면 첫 장을 선택하세요.

두근두근 급식실 · 공개 전 점검표
점검 항목확인할 곳과 고칠 방법확인
개인정보 입력란 첫 화면에서 결과까지 이동하세요. 이름, 학번, 연락처를 묻는 칸이 있으면 삭제하세요. 다시 실행해 개인정보를 입력하지 않고도 과제를 마칠 수 있는지 확인하세요.
사람 얼굴 사진 올릴 사진을 한 장씩 열고 배경에 서 있는 사람까지 살펴보세요. 얼굴이 보이는 사진은 앱 화면과 업로드할 파일 목록에서 빼세요. 위치를 알려 주려면 ‘식판 수레 옆’처럼 현장에서 찾을 수 있는 물건을 적으세요.
코드 속 인증키 main.py, 설정 파일, 화면 문구에 실제 키 값이 있는지 확인하세요. 키를 사용하는 앱은 값을 배포 설정의 Secrets에만 저장하세요. 공개할 파일 목록에서 키가 든 설정 파일을 빼세요.

실제 키를 이미 공개 저장소에 올렸다면 공유를 멈추고 선생님께 알리세요. 파일을 고쳐도 이전 커밋에 키가 남을 수 있습니다. 공개된 키를 폐기하고 새 키를 발급받아 Secrets에 저장하세요.

세 항목을 확인한 뒤 다른 기기에서 앱 주소를 새로 열어 보세요. 버튼을 눌렀을 때 팀이 정한 결과가 나오면 그 주소를 짝에게 보내세요.

④ AI 딴소리 멈추기 한 줄

AI가 부탁하지 않은 기능을 더했거나 관찰하지 않은 결과를 썼을 때 사용하세요. 1~4차시는 공통 앱을 만들던 대화에, 5차시부터는 새로 연 팀 대화에 보내세요. 대괄호 안에는 우리 팀의 버튼 이름이나 직접 확인한 내용을 넣으세요.

1차시 · 첫 화면에 기능이 너무 많을 때
이번에는 제목, ‘급식실 열기’ 버튼, 버튼을 눌렀을 때 나오는 인사말만 남겨서 main.py와 requirements.txt를 다시 보여 줘.
2차시 · 중식 표를 요청했는데 반찬 평가까지 만들었을 때
첫 화면을 유지하고 학교 검색, 지난달 중식 조회, 선생님 준비 자료 선택, 날짜별 표와 건수 확인까지만 할 수 있게 main.py와 requirements.txt를 다시 보여 줘.
3차시 · 제공 일수를 학생 선호도로 설명할 때
이 식단으로 확인할 수 있는 것은 반찬이 나온 날짜 수야. 선호도에 관한 문구를 빼고, 실제 조회 기간과 제공 일수로 반찬 순위를 설명해 줘.
4차시 · 화면을 고치면서 집계 기준도 바꿨을 때
아래 main.py에서 반찬을 세는 기준과 제외 메뉴 선택은 그대로 두고, 내가 요청한 화면 한 곳만 고쳐서 main.py 전체를 줘.
5차시 · 인터뷰에 없던 내용을 덧붙일 때
우리 팀이 쓴 내용에서 확인이 필요한 부분 하나를 골라 질문만 해 줘.
6차시 · 팀 과제에 필요 없는 기능을 더했을 때
방금 추가한 [과제에 필요 없는 기능]을 빼고, [버튼 이름]을 누르면 [팀이 정한 결과]가 보이게 해 줘. main.py와 requirements.txt 전체를 다시 보여 줘.
7차시 · 한 곳을 고친 뒤 다른 버튼이 작동하지 않을 때
6차시처럼 [원래 되던 동작]을 하면 [원래 결과]가 나오게 하고, 내가 요청한 [수정할 한 곳]만 바꿔서 main.py 전체를 보여 줘.
8차시 · 교실 시연만 보고 급식실에서도 효과가 있었다고 쓸 때
우리 팀이 교실에서 본 행동은 [상대가 한 동작과 화면 결과]야. 현장에서 아직 확인하지 않은 결과를 쓴 부분만 짚어 줘.

⑤ 8차시 밖 선택 활동 · 실제 급식실에서도 도움이 될까?

8차시 제출 카드에는 짝 팀이 교실에서 혼자 해낸 일과 도움을 받은 일을 적습니다. ‘도움이 되는가’ 칸에는 실제 급식실에서 살펴볼 행동을 쓰고, 아직 관찰하지 않았다면 수업 뒤 확인이라고 적으세요. 제출 카드를 내면 8차시 수업을 마칩니다. 현장에서도 확인하고 싶은 팀은 아래 활동을 선택하세요.

  1. 앱을 사용하기 전에 관찰하세요

    제출 카드의 ‘도움이 되는가’ 기준을 읽고 선생님과 장소, 시간대, 관찰할 시간을 정하세요. 반납 안내 팀이라면 ‘반납 순서를 묻는 질문 한 번’을 한 건으로 정할 수 있습니다. 점심 배식 시작 20분 뒤부터 같은 반납대에서 10분 동안 질문이 몇 번 나오는지 세세요.

  2. 급식실에 앱을 적용하고 같은 조건에서 다시 관찰하세요

    예를 들어 반납대를 이용하는 학생이 그곳에서 앱을 열고 반납 순서를 확인할 수 있도록 하세요. 다음 관찰도 같은 반납대에서 배식 시작 20분 뒤에 시작하고 10분 동안 진행하세요. 앞에서 정한 기준으로 같은 행동을 세세요. 사람의 이름이나 얼굴 대신 관찰한 행동과 횟수를 기록하세요.

  3. 두 기록을 선생님께 보고하세요

    “반납 순서를 묻는 질문은 적용 전 10분 동안 ___건, 적용 후 10분 동안 ___건이었습니다”처럼 직접 센 값을 말하세요. 두 값이 같거나 횟수가 늘었을 때도 그대로 적으세요. 반납대 위치가 바뀌는 등 관찰 조건에 차이가 있었다면 그 사실도 함께 보고하세요.

두근두근 급식실 · 선택 활동 보고서

관찰 전에 첫 두 줄을 채우세요. 적용 전후에는 각각 해당 칸에 기록하고, 마지막 줄에 두 결과를 한 문장으로 정리해 선생님께 제출하세요.

확인 문제

문제 1 11월에 우리 학교의 지난달 중식을 조회하다가 ‘선생님 준비 자료 불러오기’를 선택했습니다. 표에 15일이 보입니다. 어떤 기록이 맞습니까?
준비 자료를 선택하면 앱은 저장된 CSV를 읽습니다. 표 위에 표시된 학교, 연월, 자료 출처를 함께 기록하세요.
문제 2 반납 안내 앱을 적용하기 전에는 배식 시작 20분 뒤부터 반납대에서 10분 동안 반납 순서를 묻는 횟수를 셌습니다. 적용 후에는 어떻게 확인하면 좋습니까?
장소, 시간대, 관찰한 시간 길이, 한 건으로 세는 행동을 맞추면 두 횟수를 같은 기준으로 읽을 수 있습니다. 관찰한 값을 그대로 선생님께 보고하세요.
